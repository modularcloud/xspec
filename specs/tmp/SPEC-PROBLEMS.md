# SPEC-PROBLEMS

Defects in `specs/SPEC.md` found while building against it (PROCESS.md: blocking spec problems). Each entry is dated and describes the defect precisely; none is resolved here.

## 2026-09-11 — `d={}` (14, 2.7) versus "well-formed MDX" (14.20): the empty attribute value expression

- **Where.** SPEC.md 14, the range rule for a reference spelling: "a `d` value's offending expression — … the expression its braces enclose, the braces excluded as in its would-be occurrence (5.7), a zero-length span at its closing brace when they enclose no expression"; SPEC.md 2.7: "a braced `d` value that is not such a reference or array literal is a dynamic argument (14.8)"; SPEC.md 14.20: "a spec-group file that is not well-formed MDX" is unparseable, masking every condition inside it. TEST-SPEC.md T14-11 pins the consequence: `d={}` is condition 8 with the range `{"start": <offset of the closing brace>, "end": <the same offset>}`.
- **Defect.** SPEC.md never defines "well-formed MDX". Under the MDX project's reference grammar — micromark-extension-mdx-jsx 3.0.1, `lib/factory-tag.js`, tokenizes an attribute value expression with `allowEmpty = false`, and micromark-util-events-to-acorn 2.0.3 then throws "Unexpected empty expression"; the grammar `@mdx-js/mdx` compiles with — `<S id="a" d={}>` is not well-formed MDX: the file is unparseable (condition 20) and no `d` value exists for condition 8 to locate. So 14's "when they enclose no expression" clause names a construct that 14.20, read against the reference grammar, excludes, and T14-11's `d={}` arm pins behavior no product parsing MDX by that grammar can exhibit. (The same tokenizer without acorn accepts `{}` as an attribute value, so the two readings of "well-formed MDX" disagree exactly here.) Both readings put the location at the closing brace's offset as a zero-length range — under 14.20's syntax-failure rule the longest well-formed prefix ends at the brace — so only the condition (8 versus 20) is in question.
- **Observed.** The product at 9868e65 reports `d={}` as condition 20 (`unparseable-source`) with a non-zero-length range at the brace ([46, 47) on T14-11's fixture); the harness's T14-11 arm (c) asserts SPEC.md 14 and TEST-SPEC.md as written (condition 8, zero-length at the brace) and fails diagnosed against it.
- **Needed.** A decision: either define "well-formed MDX" as the reference grammar and delete 14's empty-braces clause (T14-11's `d={}` arm then becomes a 14.20 syntax-failure arm at the same zero-length offset), or define the grammar xspec parses so that an empty attribute value expression is well-formed and keep condition 8. Until then T14-11 (c) follows TEST-SPEC.md.
