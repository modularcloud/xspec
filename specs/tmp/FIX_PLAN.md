## Task 148 — Store only the texts a review payload can present, so sessions stay proportionate and `review create` succeeds at scale (SPEC 10.7, 10.2, 10.4, 10.6, 13.4, 12.0; B4)

**Requirement.** `review create` creates the session (10.7) — audit "reviews the entire workspace" (10.6) — and every outcome is exit 0, 1, or 2 (12.0); sessions are durable files (13.4). 10.2: items "MUST carry enough baseline identity and baseline text that they remain actionable after the referenced nodes are edited, moved, or deleted; the text values carried and presented are fixed by the payload rule of 10.7". 10.7: "Scope text is the scope root's subtree text for `subtree-coherence`, the scope node's subtree text for `uncovered-requirement`, and the scope node's own text for `parent-consistency`, `dependency-consistency`, and `metadata-consistency`; a code location has no text value"; "Context text is own text where the context is an ancestor chain (`subtree-coherence`, `uncovered-requirement`) and subtree text otherwise"; "A present scope or context node's text is read from the current graph; an absent one's is its value in the most recent graph state that contained it, among the item's baseline state (10.2) and the states under which mutating subcommands (13.5) derived or resolved the item with that node among its nodes"; "Origin text is instead a before/after pair of the node's own text: before, its value in the item's baseline state …; after, its value in the current graph". Nodes beneath a scope root carry no text (the payload's `scopeNodes` entries hold none; `scopeSetEntryJson` in `src/cli/commands/review-session.ts`). So a session needs, per item and node, only the text kinds that node's roles present — never both kinds of every node, and no ancestor's subtree text. (The hashes 10.4 records per scope node are required as they are; this task does not touch them.)
