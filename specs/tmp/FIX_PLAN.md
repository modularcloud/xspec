## Task 4 — Acquisition removes leftover trees whole, never following a link (SPEC 13.5, 13.4, 14.24, 14.25; B5; after Task 3)

**Requirement.** 13.5: with no live entry, "acquisition removes every leftover there — everything in the lock directory but its own entry: … anything that is no entry, a directory with all it holds and a symbolic link itself, never its target"; "Acquisition reads no file's content — it examines occupants' kinds and lists the lock directory and each directory it removes"; 13.4: writes never traverse symbolic links. So a FIFO is removed unopened, a symbolic link is removed itself (its target byte-identical in place), a directory is removed with everything it holds at every depth, and names beginning with `.` or not valid UTF-8 (P-15, Linux leg) are removed like any other. Anything in the lock directory but a plain file is no entry and records no identifier, whatever its name — so T13.5-10(e), which replaces a held run's entry, under its name, with a directory holding a file, a FIFO, or a symbolic link to a plain file outside the workspace, expects the next run to remove it and acquire. A refused listing or kind read inside a leftover tree is the read failure concerning `.xspec/lock`, and a refused removal there the write failure concerning `.xspec/lock` — never the nested path (14.24, 14.25; T13.5-10(d)'s subdirectory arms, T14-9, T14-10 (i)) — release following. Leftover directories are listed only once no live entry was found: T13.5-10(c) stages unlistable leftover directories beside a live holder and expects `workspace-busy`, never `read-failure`.

**Observed.** P-15 falsified at seed 271828183: `rename specs/A.mdx a a2 --json` leaves the staged `leftover-0` (an empty directory) in `.xspec/lock` (shrunk from a `move` beside a symbolic link whose name is not valid UTF-8). With a leftover subdirectory made unlistable, the real `rename` exits 0, expected `read-failure` at `.xspec/lock` (A4).

**Location.** Task 3's removal step, `settleLockDirectory` in `src/workspace/lock.ts` (landed): it lists the lock directory once as Buffer `Dirent`s, judges every name but its own (`listedKind` takes each kind from the listing, or by `lstat` where the filesystem reports none), throws `workspaceBusy()` on a live entry before removing anything, then unlinks the plain-file leftovers and skips every other occupant (`listedKind`'s `"other"`); refusals go through `refusedRead(…, LOCK_PATH, …)` and `refusedWrite(…, "leftover")` (`acquisitionWriteFailure` in `src/workspace/environment-refusal.ts`, whose `"leftover"` message already reads "the removal of a leftover in the lock directory .xspec/lock").
