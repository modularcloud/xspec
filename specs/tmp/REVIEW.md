## Important

- [I1] **CONF-DISC, Scope; preamble's new sentence "the configuration file is a source only where a configured group discovers it".** The workspace root always holds the configuration file (7: the root is its directory), so T7-4's bare `*` arm ("`*` does not match `.hidden`"), whose directory TEST-SPEC.md leaves open, matches `xspec.config.ts` when it is written at the root. So can any spec glob T7-5 or T7-6 stages at the root whose last segment admits a `.ts` name. Discovered by a spec group, the configuration file is a spec-group file lacking `.mdx` (14.19), and its content is analyzed as a spec source's, since an invalid path masks nothing (14). So `build` and the gated `ids` (13.3) exit 1 with 14.19 beside 14.15 at its import and 14.16 at its export, or with 14.20 where its bytes do not derive as MDX (SPEC 7; T7-10(e)(i)). CONF-DISC serves none of this. Its 14.15 is the undiscovered import target's alone, it has no 14.16, and its 14.20 belongs to code-group files. Its scope also states the opposite: 14.19 reports "T7-6's extension twin's `specs/A.txt` alone, every other staged spec-group match lacking `.mdx` a derived-classified path". Its own observation constraint also lets T7-4 and T7-5 ride `build`'s exit and findings and `ids`, and this discovery turns both to exit 1. Whether the conformer can pass T7-4 therefore depends on a choice TEST-SPEC.md leaves open, and the preamble's rule says the entry must state that choice as a staging constraint. One option: no spec glob an in-scope test of this scope stages reaches the configuration file, with T7-4's bare `*` written below the root over a directory holding only `.mdx` sources and the dotfile. The other: the scope serves the discovered configuration file's findings. The hazard predates IP 0002, but SPEC 7 and T7-10(e) now make the outcome explicit. VIOL-DISC-DERIVED's passing side already notes that the bare `*` reaches past `.mdx` names, though only as far as generated output. A code glob reaching the configuration file is harmless here: the file is then a well-formed, edgeless code source.

- [I2] **Exclusions, "T7-9 and T7-10".** The bullet concedes that T7-9(a)'s hexadecimal-escape and line-continuation arms pass every product once their literal is re-spelled, and it sends them to ride CONF-IMPORT. It leaves two more (a) arms with the same hazard under "operative assertions are positive":
  - The single-quoted `'xspec'`. A formatter or printer that normalizes quotes stages exactly its twin's `"xspec"`, and the arm then passes every product, one that reads double-quoted specifiers alone included. IMPLEMENTATION.md's Prettier at its defaults makes that rewrite in any `.ts` file it formats, should a fixture's configuration file pass through it.
  - The raw U+FFFD arm, `"x` U+FFFD `spec"`. A printer that spells non-ASCII as escapes stages it with no U+FFFD among its characters. The arm then passes the very product it names, one applying 7's U+FFFD bar to every literal as spelled (2.4).

  Name both beside the escape arms as riding CONF-IMPORT's certification representatively: P-19 draws either quote style and raw non-ASCII code points, and a printer-based corruption is one VIOL-IMPORT-BRACED catches. Then state the residual. A quote-only normalization leaves braced escapes intact, so VIOL-IMPORT-BRACED does not reach it, the same "forms P-19 draws beside it" residual CONF-IMPORT's justification already accepts. That justification's hazard list (a code printer; text decoded on its way into the harness) could name formatters too.

- [I3] **Exclusions, "The `defineConfig` module's tests".** The bullet names the pairing's residual: an edit or mutant (T7.6-3, P-18) that carries, beside its violation, an error every `defineConfig` type meets, "a repeated key say". It then dismisses the residual on grounds that do not reach it.
  - "Plain ASCII …, which no tooling rewrites" addresses normalization, not the harness's composition of the edit.
  - S-9 cannot see a repeated key. It excludes post-parse grammar checks (S-9; SPEC 14.20), and TypeScript reports a duplicate property only after parsing. Such a mutant therefore passes S-9 as well-formed, and it fails to type-check against a permissive `defineConfig` exactly as against a conforming one, its valid twin still type-checking.

  This is a negative test whose staging silently misses the behavior under test, which falls inside the preamble's own elevated class. Leaving it uncertified needs a ground that does apply. One such ground is C-1 judging whole tests: a permissive violator (the Pairing rule's `any`-typed `defineConfig`) certifies only that some arm of T7.6-3 is composed right, and certifying each arm's composition would take a violator per violation class, which is completeness, beside a conformer that serves the module channel. State that ground and accept the residual explicitly, or certify.
