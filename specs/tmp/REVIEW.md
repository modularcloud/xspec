## Important
- [I1] VIOL-IMPORT-BRACED, Deviation ("a specifier spelling one is judged not well-formed TypeScript") and Expected failures ("on each draw whose specifier spells a braced Unicode escape"). The entry never says where a braced escape begins, and whether the certification is sound depends on exactly that. A backslash escaped by a preceding backslash begins no escape sequence. So a literal holding an escaped backslash followed by the plain text `u{41}` spells a single-character escape and then ordinary characters. It contains no braced escape, and it is well-formed under 14.20. That form is exactly what the hazard this certification exists to catch produces. The CONF-IMPORT Justification describes that hazard as "a code printer serializing a drawn value". Hand such a printer, or any value serializer, the drawn spelling as content, and it escapes the drawn backslash. Every drawn braced escape then reaches the builder as an escaped backslash followed by text. Suppose the violator recognizes the braced form by its characters rather than as an escape sequence. It then refuses those draws as well, fails P-19, and so certifies P-19 against the very harness whose draws never reach the braced form as spelled. Fix: state the boundary in the Deviation. The refusal reaches a backslash that itself begins an escape sequence followed by `u{`, never a backslash escaped by a preceding one, and such a literal is read as the conformer reads it. Mirror that boundary in the Expected failures.
- [I2] The residual in the CONF-IMPORT Justification ("Certification does not reach a corruption confined to the forms P-19 draws beside it … the document accepts that residual rather than staging a violator per form, as CONF-VALID accepts its own per code point"), echoed in the Exclusions bullet for T7-9 and T7-10 ("while one that leaves braced escapes intact — quotes normalized alone, say — goes unreached").
  - The Justification names two staging hazards for P-19:
    - tooling that handles the literal as its value;
    - "a formatter normalizing quotes", which hides the single-quoted form from "a product reading double-quoted specifiers alone".
  - It certifies only the first. VIOL-IMPORT-BRACED moves no quote.
  - The ground given for accepting the second does not hold:
    - CONF-VALID's per-code-point residual covers a corruption confined to some code points of a class whose violator moves them all. It is accepted because the realistic mechanism rewrites the whole class at once ("line-separator normalization … rewrites both of its code points at once").
    - Quote normalization is a separate mechanism, and it leaves the braced form intact. It removes a whole class P-19 must reach, while VIOL-IMPORT-BRACED still fails P-19.
    - That is the case CONF-LEFTOVER's own rule addresses: "Each class has its own violator: C-1 judges whole tests, so a deviation moving both would leave one class's reach uncertified".
  - Result: a criterion-(a) reachability hazard on an in-scope property, one the document itself names, is left uncertified. Under quote normalization, a product reading only double-quoted specifiers passes both P-19 and T7-9(a)'s single-quoted arm, and certification stays green.
  - Fix, either of:
    - Add a second violator on CONF-IMPORT that refuses a single-quoted specifier as a configuration error (14.14), with P-19 as its only expected failure. That costs one deviation on an existing conformer, and T7-9's single-quoted arm would then ride on it.
    - Ground the residual on a reason that holds.
  - The raw-U+FFFD arm has the same kind of hazard wherever the step that spells non-ASCII as escapes leaves existing escapes intact. VIOL-IMPORT-BRACED catches a printer that serializes the value, not such a step.

## Optional
- [O1] CONF-IMPORT Justification ("which decoding removes and re-serialization replaces with the serializer's own") and the Exclusions bullet for T7-9 and T7-10 ("a printer serializing a literal's value leaves no braced escape"). This holds for printers that write non-ASCII code points raw or in the four-digit form. Some printers, though, write code points above U+FFFF in the braced form. A harness that re-serializes drawn values through such a printer still stages braced escapes wherever a draw holds such a code point. VIOL-IMPORT-BRACED then fails P-19 even though that harness lost every other form. Confining the deviation to braced escapes of code points at or below U+FFFF, a spelling value printers do not choose, keeps the proof sound, provided P-19's braced draws reach that range. Otherwise, qualify the claim.
- [O2] CONF-IMPORT, Scope ("no code group, `coverage`, `policy`, git, or `node_modules`"). T7-9's workspace admits a code group that does not match the configuration file ("no code group matching the configuration file"), and P-19 requires only that no group discover it. So "no code group" is a choice TEST-SPEC.md leaves open, and the conformer's ability to pass depends on it, since it serves no code group. Under the preamble's rule, that choice belongs in the entry's staging constraint, beside the one on the sources' content.
- [O3] Exclusions bullet for T7-9 and T7-10 ("every FIFO … is asserted afterwards still a FIFO in place (S-3), so a staging that misses fails loud against a conforming product"; "The trap package of T7-9(d) … is the one staging there that no assertion braces"). Two checks are in play: the in-place check, and the verification of T7-9(c)'s permission stagings on the harness itself. Both brace a staging's effect where the harness placed it, not where it was placed. The placement that matters is the path the specifier designates or, in T7-9(d), the place where resolving `N` from the configuration file's directory looks. A FIFO, refused file, or installed package placed anywhere else is met by no product, conforming or not, so the arm passes every product. The FIFO-manifest arm's catch of a silent-fallback loader, which the trap's residual leans on, rests on the same unbraced placement. The exclusion may still stand on the cost argument, but the residual as stated is narrower than the one actually accepted.
