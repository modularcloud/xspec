## Important
- [I1] T7.6-2, P-18, and section 7's CLI tests (T7-3, T7-6): two kinds of value that 7 admits are never staged. (i) An empty glob list. 7 bars an empty list only for `targetTags`, `edgeKinds`, a rule's `kinds`, and a selector's `tags` (7.4, 7.5, 14.14; these are the four lists 7.6's type-error class names), so `specs: { product: [] }` and a code group's `[]` are valid under 7. (ii) A repeated element in a set-read list. 7.4 and 7.5 read `targetTags`, `edgeKinds`, `kinds`, and a selector's `tags` as sets, and a repeated element collapses (T7.4-1 and T7.5-1 assert this at the CLI). 7.6 requires every covered file that is valid under 7 to type-check. No file of T7.6-2(a)–(f) holds either form, and P-18 is not told to draw them. So a `defineConfig` type that types glob lists as non-empty tuples (carrying 7's non-empty rule for those four lists over to globs), or a set-read list as a duplicate-free tuple, passes T7.6-1 through T7.6-7 and P-18. This is the same family of deviation as the non-empty `coverage`/`policy` demand that T7.6-2's closing sentence already names. No CLI test stages an empty glob list either: T7-6's "group with no matches" uses globs that match nothing. Fix: add both forms to T7.6-2(f) (a spec group and a code group whose glob list is `[]`, and a repeated element in each set-read list), have P-18 draw them, and add a CLI arm in which `product: []` loads, the group discovers zero sources, and `inventory` reports the empty list. (If 7 is read to bar an empty glob list after all, the CLI arm asserts 14.14 instead and T7.6-2 leaves the form out. Either way the suite must stage it.)
- [I2] T7-2: no arm wraps an admitted form in a parenthesized or TypeScript-only expression. 7 admits exactly a default export of one call to the binding whose sole argument is statically literal, with "no other statement or expression form" (14.14). T7-2's non-literal arms (spread, computed key, template literal, identifier reference, function call, number where a boolean is expected) each replace a literal; none wraps one. Add these arms, each over an otherwise valid argument and each expecting 14.14, exit 2: `export default defineConfig({…}) satisfies object`, `export default (defineConfig({…}))`, `export default defineConfig({…})!`, `export default defineConfig({…} as const)`, `export default defineConfig(({…}))`, and a wrapped value (`emit: true as boolean`, `specs: ({…})`). A loader that skips TypeScript's outer expressions accepts exactly these forms; 4.6 itself calls such wrappers "another expression". 7.6's type contract also makes `as const` and `satisfies` the idioms a TypeScript author reaches for, so their refusal needs a discriminating arm.
- [I3] H-2 (module channel), 7.6's Placement rule, and C-2: the phrase "the product's package directory, exactly as distributed" is not tied to what the distribution actually contains. Read as "the directory holding the package's manifest", it admits a development tree. Copied to `node_modules/N`, such a tree brings its installed dependencies (its own `node_modules`) along. A package whose declaration files or entry import another package then resolves that package inside the copy, and T7.6-1 through T7.6-7, P-17, and P-18 all pass, even though 7.6 requires that nothing else need be installed and that installation be placement alone. That clause is then assumed rather than tested. State that the directory given holds exactly what the distributed package carries and nothing installed into it afterwards, and is never a development tree.

## Optional
- [O1] T7.6-7(a), (c): on the static-`import` route the importing module cannot itself register its `warning` listener, or first read the observed state, "before the load". Every static dependency is resolved and loaded before any module of the graph evaluates, and the runtime's own resolution-time warnings (DEP0151 along `import`) are emitted during that loading. Say that both happen before the importing module's own loading begins. As written, the gap shows up only when S-10's DEP0151 stand-in fails the output oracle.

The answer therefore decides what the loader accepts and whether 7.6's covered files include the form, and the test spec cannot pin either until SPEC does. Tentative read: both are a configuration error (14.14), because the file's parts are enumerated exactly and neither form carries anything 7 reads.
